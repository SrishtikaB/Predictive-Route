# PredictiveRoute

**ML-Based Network Congestion Prediction and Prevention Using Machine Learning and Rule-Based Traffic Routing**

A basic, beginner-friendly B.Tech Computer Networks project in Python.

> ## Important: this is synthetic and simulated
> * The **dataset is synthetic**. It is generated by a random number generator, not captured from a real network.
> * The **routing results come from a small Python simulation**, not from a real physical network, router, or traffic trace.
> * Do **not** claim real-world performance from these results. They only show how the idea behaves inside this simplified model.

## What it does

1. Generates a synthetic dataset (2000 rows) with: bandwidth utilization, traffic load, latency, packet queue length, and a congestion label (0 = no, 1 = yes).
2. Trains a `RandomForestClassifier` (80% train / 20% test) and prints accuracy, precision, recall, F1-score, and the confusion matrix.
3. Simulates two routes (Route A and Route B), each with its own capacity, latency, and background traffic.
4. Compares two routing strategies:
   * **Static routing**: always uses Route A.
   * **Predictive routing**: the model looks at the current route's latest measurements. If it predicts congestion, it switches to the other route, but only if that route has enough free capacity for the traffic flow.
5. Runs both strategies under **Low, Medium, High** traffic and compares **average latency**, **packet loss**, and **route changes**.
6. Saves plots and CSV files in `results/`.

## How to install and run (Windows + Cursor)

1. Install Python 3.9 or newer from python.org. Tick **"Add Python to PATH"** during installation.
2. In Cursor: **File > Open Folder** and choose the `PredictiveRoute` folder.
3. Open the terminal: **Terminal > New Terminal** (or press `` Ctrl+` ``).
4. (Recommended) create a virtual environment:
   ```
   python -m venv venv
   venv\Scripts\activate
   ```
   If PowerShell blocks activation, run `Set-ExecutionPolicy -Scope Process Bypass` and try again. Or just skip this step.
5. Install the libraries:
   ```
   pip install -r requirements.txt
   ```
6. Run the project:
   ```
   python main.py
   ```
   (If `python` is not found, try `py main.py`.)

It takes only a few seconds.

## Understanding the output

**Model scores** (on the held-out synthetic test set):
* *Accuracy*: share of all predictions that were correct.
* *Precision*: when the model says "congestion", how often it is right.
* *Recall*: of all real congestion cases, how many the model caught.
* *F1-score*: a balance of precision and recall.
* *Confusion matrix*: rows = actual, columns = predicted. Top-left = correct "no congestion", bottom-right = correct "congestion", the other two cells are mistakes.

These scores are high partly because the synthetic labels are built from the same features, so do not read them as real-world accuracy.

**Simulation table**: one row per traffic level and strategy:
* `avg_latency_ms`: average delay experienced by our traffic flow (lower is better).
* `packet_loss_pct`: share of our traffic dropped because a router queue was full (lower is better).
* `route_changes`: how many times the strategy switched routes per run.

Each number is the average of 10 simulation runs (300 time steps each) using random traffic. Both strategies receive the exact same traffic in each run, so the comparison is fair. A fixed random seed makes the output repeatable.

**Files in `results/`**
* `latency_comparison.png`, `packet_loss_comparison.png`, `route_changes_comparison.png`: bar charts comparing the strategies.
* `comparison_results.csv`: the simulation table.
* `synthetic_dataset.csv`: the generated dataset.

## How the simulation works (simple version)

* Each step is 1 second. Every route receives background traffic from other users, and our flow goes to whichever route is currently chosen.
* If traffic exceeds a route's capacity, the extra waits in a queue. If the queue is full, packets are dropped (packet loss).
* Latency = base route latency + a small load-based delay + time spent waiting in the queue.
* Traffic includes random bursts so that congestion actually happens.

## Limitations (please mention these in your report)

* Synthetic data and a simplified simulation, not a real network. No real packets, protocols, or hardware.
* The model classifies congestion from the **latest measurements**; it is a simple classifier, not a forecasting model of future traffic.
* Route A is overloaded more often than Route B by design, so the setup gives predictive routing room to help. Changing the settings at the top of `main.py` will change the results.
* At Low traffic nothing is congested, so both strategies behave identically (0 route changes).
* At High traffic, predictive routing switches routes many times (route "flapping"). Fewer switches would need extra logic (for example a cool-down timer), which was left out to keep this version basic.
* Model and simulation parameters were chosen by hand and not tuned to a real system.
